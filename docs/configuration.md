# Configuration reference

All documents use strict JSON Schema draft 2020-12 and `schema_version: 1`. Unknown fields and duplicate YAML mapping keys fail. Paths are interpreted relative to the configuration directory unless absolute paths are permitted by the selected policy.

## `authority.yaml`

```yaml
schema_version: 1
authority:
  id: team-a
  fail_closed: true
  fixture_policy: none
```

`id` is lowercase alphanumeric/hyphen and begins with a letter. `fail_closed` can only be true. `fixture_policy` is `none` or `safe-main-example`; the latter is reserved for the `main-example` fixture and restricts relative targets to `var/example-targets/`.

## `sources.yaml`

```yaml
schema_version: 1
sources:
  - id: shared
    type: git
    location: /reviewed/local/or/remote.git
    track: main
    skill_root: skills
```

`type` is `git` or `filesystem`. Git requires `track`; filesystem forbids it. `skill_root` is a confined relative POSIX path. Filesystem source paths retain their lexical identity and reject symlinked/non-directory ancestors during lock. Source trees reject broken/escaping links and unsupported special files. Git access is non-interactive and bounded, but source trust remains an operator decision.

## `pool.yaml`

```yaml
schema_version: 1
skills:
  - shared/review
```

The list is unique and non-empty. Each canonical ID begins with a configured source ID and contains safe non-empty path segments. The pool is the authority's delegation ceiling; locking does not automatically add discovered skills.

## `delegations.yaml`

```yaml
schema_version: 1
targets:
  - id: worker
    root: ../var/example-targets/worker
    grants:
      - shared/review
```

Target IDs are unique. Roots normalize lexically. Grants are unique and non-empty, must be a subset of the pool, and must exist in the exact lock. Two target declarations cannot occupy the same normalized artifact path. Duplicate runtime names among a target's grants fail closed.

## `skill-lock.yaml`

Generated by `skillctl lock` or an explicit `update SOURCE|--all`:

```yaml
schema_version: 1
sources:
- source_id: shared
  type: filesystem
  tree_hash: <64 lowercase hex>
  skills:
  - canonical_id: shared/review
    runtime_name: review
    path: skills/review
    sha256: <64 lowercase hex>
```

Git uses `resolved_commit` (40 lowercase hex) instead of `tree_hash`. Configured and locked source sets and types must match exactly. Canonical prefix/suffix, configured skill root, locked path, runtime name, pool, grants, and content hash are revalidated at consumption boundaries.

## Generated state

- `var/cache/sources/...`: immutable content-addressed source snapshots.
- `<target>/.skill-delegator/managed.json`: strict ownership and exact managed-entry evidence.
- `<target>/.skill-delegator/operation.lock`, `staging/`, `backup/`, `failure.json`: transaction internals/failure evidence.
- `var/receipts/<sha256>.json`: canonical verification receipts.

Keep `var/` ignored. Do not commit generated cache, target, transaction, or receipt data as configuration.
