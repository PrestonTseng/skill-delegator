# Deterministic Evidence Review

Use this skill when reviewing code that reconstructs state or computes reports from immutable/versioned evidence, especially daily aggregates, financial reconciliations, event ledgers, audit trails, or point-in-time windows.

## Core Principle

A green suite proves the tested examples, not the evidence boundary. Review both the declared contract and the executable behavior. Prefer temporary, checksum-valid adversarial fixtures over speculative findings.

## Workflow

1. **Pin scope and authority.** Record the exact diff, HEAD, binding brief/spec/design, and explicit non-goals. For uncommitted worktree reviews, use `HEAD` as the baseline and inventory `git status --short`; `git diff` omits untracked files, so inspect relevant untracked source/spec/test files separately. Do not perform live writes, scheduling, network access, or mutation unless authorized.
2. **Stabilize the observed snapshot.** Assume a shared worktree or index may change concurrently. For staged reviews, capture `git write-tree` as the immutable index identity; status and diff text alone are not stable identities. If the exact diff digest is part of the deliverable, save the non-empty diff bytes and their digest at capture time; never recompute an emptied `git diff --cached` after a concurrent commit and present the empty-stream SHA as the reviewed digest. Repeat the tree hash immediately before final verification. If staged and unstaged content overlap, do not run repository commands against the working tree and call that staged verification: materialize the index with `git checkout-index --all --prefix=<isolated-root>/`, run from that root, and use only approved ignored fixtures. Choose a root visible to Docker or other sibling runtimes, verify cleanup, and remove it afterward. If the tree changed, discard stale conclusions, reread affected source/spec/tests, and rerun targeted/full gates against the final snapshot. Never combine code evidence from one tree with test evidence from another. If the index becomes empty because the change was committed during review, compare the reviewed tree to `HEAD^{tree}`, report the exact commit/tree when they match, and retain the originally captured non-empty diff digest as the reviewed-delta identity. If a newly added test conflicts with the binding spec, report the contract conflict explicitly instead of treating either side as silently authoritative. See `references/exact-staged-artifact-review.md` and `references/backup-publication-race-probes.md`.
3. **Map the evidence boundary.** Identify discovery, path validation, checksum/schema verification, chronological reduction, metric policy, and serialization functions. Use structural code search first, then read exact source. Trace versioned policy bytes end to end: loading, manifest commitment, publication verification, immutable-history representation, and every downstream interpreter. Do not treat a free-form `policy_id` or publication-time hash check as sufficient if historical consumers discard or ignore the committed hash. In policy tests, assert the full expected digest of the exact canonical bytes—not merely that the result is 64 hexadecimal characters—so hashing the wrong byte representation cannot pass.
4. **Separate review axes.** Keep spec compliance and code quality as distinct verdicts. Passing one cannot mask failure of the other.
5. **Reject circular equivalence proofs.** When a refactor claims byte-for-byte compatibility, `public_wrapper(new) == private_core(new)` only proves delegation, not preservation. Require a committed oracle captured on the accepted base: literal canonical bytes, stable scenario inputs spanning both sides/modes and accounting boundaries, and a base-pass commit that predates production. An uncommitted `/tmp` comparison or report-only assertion is supporting context, not reviewable acceptance evidence.
6. **Trace attribution semantics.** For every event class, distinguish event time, run/observation time, completion/publication time, and reporting-window membership. For canonical event-and-side dedupe, prove the identity serialization is injective over accepted fields: delimiter joins require escaping/rejection or structured/length-prefixed bytes. Then verify same-event opposite sides follow the declared contract, first-observation evidence is frozen, and accepted repeats are skipped before order creation/classification. After any hash-validator hardening, audit old negative tests for invalid baselines: require a canonical baseline plus a positive match control before mutation, or every rejection may pass tautologically. Use `references/canonical-event-side-dedupe-review.md` for the focused identity, ledger, test-quality, and evidence checklist.
7. **Probe adversarial histories.** Create fixtures only in temporary directories. Keep them structurally and checksum valid except for the single property under test.
8. **Verify numeric truth and fail-closed parsing.** Test hostile ambient numeric context, exact reconciliation, exact zero, and post-aggregate domain bounds—not only individual input bounds. In Python `Decimal` pipelines, audit unary sign operations before exact sums or fixed-context ratios: `-value` can round under the ambient context, so use `copy_negate()`/`copy_abs()` when the operation must preserve the full coefficient. Keep strict validator bounds unchanged and prove builder output passes them. For JavaScript/TypeScript evidence validators, explicitly probe missing and non-numeric metadata: require `Number.isFinite()` before monotonicity or tolerance comparisons, because `NaN` makes ordinary `<`, `<=`, `>`, and equality guards false-pass. Require source/output durations to be finite and positive before computing tolerances, and reject absent packet timestamps before claiming strict ordering. A valid happy-path fixture does not prove the validator fails closed. For the Decimal regression and captured-replay verification pattern, read `references/ambient-decimal-derived-metrics.md`.
9. **Verify confinement and immutability.** Probe symlinks at every discovery and artifact level, including empty-target and dangling directory links that never reach per-run verification. Check each node with `is_symlink()` before `exists()`, `is_dir()`, filtering, or iteration can follow or silently ignore it. For a target that may be absent, never accept `lexists(exact_target) == false` as proof of a safe empty placement: walk every existing ancestor with `lstat`, reject symlink ancestors and non-directory blockers, and test both an existing leaf reached through a symlink ancestor and an absent leaf beneath one. When a handwritten metadata parser and a published JSON Schema describe the same ownership document, run differential fixtures through both; any schema-invalid document accepted as manager-owned is fail-open, especially if it can authorize removal. See `references/hostile-state-planning.md` for compact probes. Also verify future-file exclusion and before/after evidence-tree identity for read-only paths. For writable caches, static `lstat` plus later path-based operations is not sufficient: audit same-UID directory-replacement TOCTOU and prefer retained `O_DIRECTORY|O_NOFOLLOW` descriptors with `dir_fd` operations. Do not assume that calling `os.listdir()` twice on the same retained, already-enumerated directory FD proves a fresh final entry set: adversarially add a valid direct child during parsing and require detection. Re-enumerate through a fresh descriptor bound to the retained directory identity, then compare the complete byte-sorted name set and each child's device/inode identity. Treat retained directory identity, nested no-follow reads, opened-child identity, and final entry-set rebinding as four separate closure claims; a directory-path replacement test proves only part of them. See `references/descriptor-directory-entryset-rebinding.md`. Treat each `open → verify → return fd` helper as an ownership transfer: fault-inject `fstat`/mode-repair/`fsync` failures (including `BaseException`) and prove the newly opened fd plus already-owned parent descriptors close without masking the primary error.
10. **Verify provider realism and cache durability.** When a pipeline consumes an external API, compare strict fixtures with the maintained provider schema and run the narrowest read-only live probe that can reveal real keys, timestamp granularity, ordering, and boundary behavior. A strict validator that rejects the provider's documented extra fields or truthful millisecond jitter is not correct merely because synthetic fixtures pass. For durable caches, audit the full metadata chain: file fsync, atomic no-overwrite publication, containing-directory fsync, ancestor fsync after new directory creation, EEXIST cleanup fsync, reread, and ownership-safe failure cleanup. Fault-inject every operation after resource acquisition and before ownership transfer; prove the exact descriptor closes, include a direct `BaseException` case, preserve the primary exception if cleanup fails, and verify already-owned parent resources close when later child validation fails. Adjudicate the primitive by semantics rather than wording: a same-directory hard-link install may be equivalent-or-stronger than literal rename when no-overwrite is binding. When a hardened caller and loader compose, test the real default adapter end to end: do not disguise retained fds as `/proc/self/fd` Paths for a no-follow Path API; use a descriptor-native borrowed-fd contract with a separate display path. For directory-level evidence publication, also rebind the final public pathname to the retained publication inode after rename, open artifacts before `fstat` type checks, and quarantine/delete only identity-verified objects. For replace-in-place SQLite backups, race both an existing target and an initially absent target; compare every successful call's returned digest with the final public bytes, and inject rollback failure after a primary directory-fsync failure to prove cleanup cannot mask the primary exception. Use `references/backup-publication-race-probes.md` for deterministic interleavings, storage-lineage truncation probes, and the exact staged-digest rule. Use `references/provider-backed-cache-review.md` for descriptor-native composition and `references/immutable-publication-toctou-review.md` for the publication state machine and fault matrix.
11. **Verify output truth.** Check canonical ordering, byte-identical stdout for identical inputs, explicit denominators/sample counts, and unambiguous scope labels. When a renderer accepts an arbitrary result Mapping, treat it as a second evidence boundary: mutate one valid result at a time and require rejection of parent/child count or cash contradictions, paired-count/delta drift, non-boolean gates, fabricated counts, and gate/reason/status disagreement. Do not confuse local cash identity or deterministic bytes with semantic reconciliation. Before an expensive final replay, build a design-to-manifest closure matrix: arithmetic evidence is not detached provenance, and source-series hashes do not replace request, endpoint, quality, dirty-state, segment-boundary, or exact cache-envelope commitments. If an immutable package is provenance-incomplete, preserve it and republish a reviewed versioned package rather than overwriting it or wasting a rerun on the obsolete schema. For the full byte-bound provenance and remediation checklist, read `references/immutable-screening-publication-provenance.md`. For PF, explicitly test mixed, all-win, all-loss, all-breakeven, and empty/OPEN cohorts; all-loss is numeric zero, while null means neither positive nor negative cash exists. Require plain exponent-free Decimal text and document any deterministic ratio-rounding context. Separate exactly-once immutable event identity from external notification delivery: without a transactional acknowledgement boundary, stdout/chat delivery is best-effort or at-least-once—not exactly-once. See `references/aggregate-screening-render-review.md` for the full reconciliation matrix, PF ordering table, adversarial mutations, and TDD-history audit. For release review of package exclusions, configured flush timing, batched delivery, and cross-process deduplication, use `references/notification-batching-dedup-review.md`; it requires mutation-sensitive fictional package fixtures, injected-clock flush boundaries, one single/batch dedup authority, minimal redacted durable state, and fresh-process replay probes.
12. **Run real integration gates.** Execute targeted/full tests, compile/build, and diff checks, then probe the production wrapper from a clean shell. Test the actual module import path, timeout grammar and total scheduler budget, executable bit, zero-byte silence, path confinement, and process-level lock behavior. Pytest configuration can mask a broken production `PYTHONPATH`. For publication CLIs, distinguish a realistic fresh-process trust boundary from impossible same-interpreter anti-monkeypatch claims: enforce an isolated interpreter, clean committed source, disabled worktree bytecode lookup, and an explicit manifest boundary instead of trusting mutable function metadata. For src-layout uv projects, verify `uv run --isolated --with-editable . python -I -X pycache_prefix=/dev/null -m ...` end to end. A clean Git tree is not enough: timestamp-valid ignored `.pyc` can execute instead of committed `.py`; require a control/protected poisoned-bytecode regression and fail closed unless loaded critical-module cache paths route under `/dev/null`. See `references/isolated-evidence-execution-boundary.md` for the threat model, checks, poisoned-bytecode probe, and expensive-replay capture pattern. For pytest-conftest relocations and duplicated OS jobs collapsed into a matrix, use `references/pytest-ci-matrix-review.md` to prove suite-wide plugin discovery, pre-body sentinel enforcement, wheel-versus-sdist truth, exact gate parity, semantic mutants, and explicit matrix fail-fast evidence retention. When formatters or linters must exclude provenance-bound source snapshots, use `references/provenance-snapshot-tooling-boundaries.md` to prove the exclusion is project-root-scoped, maintained code remains covered, and snapshot bytes remain identical in a disposable authority overlay.
13. **Write a decision-ready report.** Include severity-ranked findings, exact code locations, reproduction output, required remediation, separate spec/quality verdicts, and an explicit approval decision.

For closed-bar trading-indicator chains, use `references/closed-bar-indicator-chain-review.md`. It covers dependency status algebra, actual first-traversal extreme freezing, strict event/known-time composition, source-valid parameter-shape translation, exact-type boundaries, prefix invariance, and the rule that green quality/replay gates cannot mask semantic fail-open defects.

When the implementation is already committed and the missing deliverable is a no-product-change redo evidence package, use `references/redo-evidence-package.md`. It covers accepted-history test-first proof, historical versus reconstructed RED with **Git-tree and Python-environment isolation** (to prevent shared editable installs from creating false GREEN), fresh GREEN evidence, collector-based exact-count recovery, adjudication of mandatory GREEN test-signature adaptations without accepting assertion weakening, accepted-base type debt, complete finding dispositions, and atomic hard-link versus literal rename analysis.

For external-provider historical loaders and durable no-overwrite caches, use `references/provider-backed-cache-review.md`. It covers live-shaped fixture realism, stable request versus source identity, strict funding-slot validation without timestamp repair, hard-link publication adjudication, ancestor-directory fsync, EEXIST residue, and descriptor-confined no-follow I/O.

For exceptional resource-ownership leaks, use `references/resource-ownership-fault-injection.md`. It provides the acquire/verify/transfer contract, post-acquisition fault matrix, exact-FD plus process-count leak proof, archive-based independent RED/GREEN verification, successful-transfer and exactly-once controls, `BaseException`/traceback/cleanup-failure coverage, parent/child orchestration checks, and strict tests-only/production-only commit sequencing.

## Remediating Review Findings

When the task is to fix a completed review rather than perform one:

1. Read the finding report together with the originating brief, implementation report, and approved lower-level primitive. The finding text alone may omit binding interface and reporting requirements.
2. Build a finding-to-regression matrix before production edits. Include every explicitly named omitted adversarial case, not just the headline findings.
3. Run the whole focused matrix once and preserve aggregate RED evidence. A collection error or unrelated fixture error is not valid RED; correct it until failures demonstrate the missing behavior.
4. Fix causes at shared seams. If a report consumer copied lifecycle or arithmetic logic, extract one chronological reducer that returns transition metadata plus final state, and one bounded exact-arithmetic primitive. Keep window attribution and presentation in the consumer.
5. Preserve point-in-time layering: filter future runs before opening them; fully verify all supporting runs that are needed for state; parse window-only health/filter metadata only when its reporting scope requires it.
6. After GREEN, verify synthetic adversarial fixtures and the existing published history in a read-only probe. Boundary hardening must reject hostile evidence without making valid legacy evidence unreadable.
7. For point-in-time candidate decisions, split overlay handling into two phases: globally scan every present identity and timestamp first, then classify candidate-local schema availability. Never let a malformed-first frame hide future evidence later in mapping order. Validate advertised public completion helpers directly rather than relying only on their caller.
8. Preserve truthful audit evidence on every local `UNAVAILABLE` path: available counts, computed raw scalars (including zero denominators), and latest contributing cutoffs. Use one canonical extractor across success and early-return paths, and type it with the contract's immutable scalar/key-value aliases instead of `type: ignore` escapes.
9. Append finding dispositions, actual RED/GREEN commands and counts, read-only production-fixture evidence, and prohibited actions not taken to the existing implementation report. Then run fresh targeted/full verification before commit and prove the staged path list matches authorized scope. Before a subagent writes a generic `.superpowers/sdd/task-N-report.md`, `task-N-brief.md`, or `progress.md`, check `git ls-files --error-unmatch <path>`: inherited branches may already track those names from an earlier plan. Namespace the new brief/report/ledger under a feature- or parent-task-specific subdirectory and preserve the prior artifact rather than overwriting it. Check whether the required report is tracked before staging: ignored reports need an explicit, narrowly scoped `git add -f <exact-path>` only when the user requires them committed. If the report must name the implementation commit, commit code/tests first, record that SHA in the report, and use a separate report commit rather than attempting a self-referential amend.

See `references/review-remediation.md` for a compact regression matrix and reducer design pattern. For aggregate screening/render contracts, `references/aggregate-screening-render-review.md` includes complete-screen recomputation, concentration-gate semantics, diagnostic reconciliation, rigorous half-ULP Decimal bounds for averages/PF, coherent one-invariant mutation design, and positive controls for legitimate 28-digit `ROUND_HALF_EVEN` output. For bar/diagnostic/overlay candidate pipelines, use `references/point-in-time-candidate-remediation.md` for the fail-closed precedence matrix and two-phase overlay pattern. When remediation must replace a duplicated downstream bundle validator with an upstream pure normalized validator while restoring exact nonzero funding and boundary evidence, use `references/shared-normalized-validator-remediation.md`; it includes honest immediate-GREEN versus genuine-RED provenance, canonical fixture hashes, two-level delegation sentinels, long-hold plus focused-boundary tests, mutation-sensitivity checks, structural preservation of the upstream validator, and the final cumulative approval audit.

### Time-boundary fixes and cron-resume gates

For scheduler incidents involving bars, windows, leases, or other time-bucket successors:

1. Name the authoritative cutoff and trace it from normalization through the changed decision. Distinguish canonical run/event cutoff from wall clock, collection completion, retrieval time, and evaluation time; a correct boundary fix must not silently substitute one for another.
2. Express the contract as a strict inequality and test all three regions: before due time (defer with no transition/error), exact equality (the successor is due and missing evidence fails closed), and after due time (normal gap/continuity checks apply).
3. Reproduce RED from the pinned base in a disposable archive by overlaying only the candidate regression test. A setup/import failure is not RED. Preserve the exact failure count and show that the equality control already behaves as intended when applicable.
4. Verify the real integration path, not only the helper: publication status, blocker codes, zero/new transition bytes, reconstructed prior state, and unchanged fail-closed regressions.
5. Validate natural immutable evidence independently: inspect the incident cutoff, available predecessor/successor timestamps, next publication, aggregate schema, supporting versus in-window counts, reconciliation, and before/after evidence-tree digest.
6. Treat controller probe/parser mistakes separately from product failures. Re-read the actual output schema before rerunning; never downgrade valid aggregate evidence because an ad-hoc checker guessed a field name.
7. Scope approval narrowly: one controlled trigger plus the first natural proof, with read-only reconciliation after each and explicit pause conditions. Code-gate approval does not close the incident until the fixed branch is naturally exercised.
8. If a packaged diff does not byte-match default `git diff`, inspect its hunk context width or metadata before calling it stale; verify the exact rendering (for example `--unified=N`) or reverse applicability.

### Strict JSON contract and generated-brief gates

For strict JSON validators, test JSON-native scalar and container types as separate adversarial classes, including equal-valued integer/float pairs, Python's boolean-as-integer trap (`False == 0`, `True == 1`, and set-membership false passes), and malformed nested list items. Require exact native type checks before numeric domain, initial-state, transition, flip, ordering, or direction logic. For integrity-indexed packages, canonically rewrite each mutation and regenerate all dependent manifest identities and checksums before invoking the real validator; stale-index rejection is not semantic proof. Exercise the real CLI as well as the validation API: each malformed case must exit nonzero with its intended diagnostic and **without** a traceback. After structural errors, do not continue into a generated-document renderer that assumes valid mappings or lists. In final remediation reviews, rerun the original matrix, then systematically substitute both booleans across every equivalent nested numeric location and require 100% rejection before approval. See `references/strict-json-contract-review.md` for the type matrix, validation-to-render pitfall, full-reindex mutation rule, and integration closure ladder.

For configuration/lock verification receipts, additionally prove that any attached Git commit governs the exact bytes hashed—not merely tracked pathnames, which may be symlinks to external bytes. Use descriptor-relative no-follow traversal from the filesystem anchor; a final-file `O_NOFOLLOW` open after pathname-based ancestor checks still loses to ancestor replacement. Combine target and source tampering so target-scan failure cannot hide skipped desired-source verification; adversarially test exact filename-set and source-type/revision coherence rather than relying on whole-object `uniqueItems`; and fault-inject every receipt-publication phase to ensure raw filesystem errors cannot escape the documented blocked/no-traceback CLI boundary. Require an atomic public outcome: reported failure leaves no newly published receipt, while success may retain it. Reject `converged` evidence unless all desired links are verified and fingerprint/count evidence is coherent. ## Mandatory Adversarial Checklist

- UTC half-open start/end boundaries.
- Future canonical evidence remains unopened.
- Malformed supporting pre-window truth fails when required for as-of-end state.
- Pre-window OPEN to in-window RESOLVED transition.
- Prior RESOLVED replay is not counted again.
- Duplicate versus unique event attribution.
- Same-timestamp deterministic ordering and zero intervals.
- Exact-zero win/loss/breakeven policy.
- BLOCKED/degraded rows excluded from strategy, filter, and PnL evidence but retained operationally.
- Every row timestamp is causal relative to run completion.
- Individual artifact symlinks cannot escape the root.
- Discovery fails closed for symlinked history roots, day entries, and run entries even when targets are empty or missing; real empty directories and regular lock/control files remain valid.
- Aggregate results are validated against the same numeric domain as inputs.
- Governed decisions prove both semantic consistency and exact policy-byte provenance at historical interpretation time; an annotation without its expected manifest policy hash is rejected, while true legacy absence follows the documented compatibility path.
- In-window counts are distinct from all-history supporting verification counts.
- Complete event ledger supports recovery from missed notifications.
- Wrapper is bounded, read-only, deterministic for explicit inputs, and free of network/LLM/mutation seams.

## Quality Smells to Watch

- A report layer duplicates the authoritative state reducer.
- A new exact-sum helper diverges from an existing hardened primitive.
- One large function mixes discovery, verification, reduction, metric policy, and rendering.
- Tests construct only happy-path BLOCKED/degraded fixtures with no otherwise-valid strategy rows.
- A field named `run_count`, `rate`, or `losses` omits its scope or denominator.

## Reporting Rules

- Quote actual probe output; do not invent expected failures.
- Describe strengths as well as blockers.
- For expectancy or strategy-research reports, issue separate **Evidence integrity** and **Recommendation quality** verdicts. Exact cash/cohort reconciliation can pass while causal interpretation or the promotion design still requires revision; never let arithmetic approval imply strategy approval.
- When a review finds interpretive or experiment-design defects, create a finding-to-disposition matrix, revise the existing report rather than hiding the original verdict, and run fresh assertions/hash/diff checks before closing the task.
- Do not approve live execution while any evidence-integrity, causal-lookahead, confinement, or accounting-domain finding remains high severity.
- Mention when the requested report path is ignored/untracked so the controller can deliberately preserve it.
- When a decision-maker asks for a simpler explanation, do not restate the whole audit. Use three compact sections: **current state**, **next action**, and **approval requested**. Keep only decision-relevant numbers and name prohibited side effects explicitly.
