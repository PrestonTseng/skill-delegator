# Confluence candidate page pattern

Observed source pages under `2026 Candidate Overview` (`3664576575`) show this practical rule:

## When to create a page
Create a candidate page by default for candidates that are clear shortlist / pass-forward candidates.

In the 2026-06-17 batch, pages were created for:
- `2026 - Mr. 詹舜凱 - Full Stack Engineer - Stage 1` (`3801219073`)
- `2026 - Mr. 劉哲豪 - Full Stack Engineer - Stage 1` (`3800924168`)

These were the clear interview recommendations from that batch.

## When not to create a page
If the recommendation is only conditional, lower-priority, or likely pass, skip page creation by default and mention the skip explicitly in the final summary.

## Page content pattern
Shortlist pages follow this structure:
1. `Candidate Info`
2. `Pipeline Overview`
3. `Stage 0 — Resume Review`
   - reviewer
   - date
   - result
   - concise review summary
   - suggested focus for HR screening call
4. placeholder sections for Stage 1–4 and Final Decision

## Practical note
Use the existing page examples as the formatting/template source rather than inventing a new layout.
