# Thalos Nibble FSM / Executor Documentation Updates

Use this reference when updating `/opt/data/workspace/tapas-icd` Thalos docs after Thalos nibble FSM or executor changes.

## Source-of-truth files to inspect

In `/opt/data/workspace/thalos`:

- `thalos/core/fsm/nibble_fsm.py` — authoritative nibble state enum, transitions, retry mapping, terminal/error sets.
- `thalos/core/nibble_executor.py` — runtime semantics for block entry, route authority evaluation, MA refresh, `AWAIT_BLOCK_EXIT`, recheck listeners, terminal nibble behavior, cleanup/termination.
- `thalos/core/mission_executor.py` — mission-level nibble orchestration, especially one-look-ahead nibble execution while the current nibble waits for block exit.
- `grafana/dashboards/thalos-realtime.json` — useful cross-check for current numeric nibble state mapping.

In `/opt/data/workspace/tapas-icd`:

- `config/docs-config.ts` — current `thalosConfig.versions.current.label`.
- `thalos/nibble_state_machine.mdx` — primary page to update.
- `thalos/mission_error_recovery.mdx` — recovery/debug guidance that often goes stale when nibble states change.
- `thalos_versions.json`, `thalos_versioned_docs/`, `thalos_versioned_sidebars/` — generated by Docusaurus versioning.

## Workflow reminder

1. Confirm repo status in both `thalos` and `tapas-icd`.
2. Read current Thalos label from `config/docs-config.ts`.
3. Freeze the old current Thalos docs **before** editing current docs:

```bash
npm run version:thalos -- <old-thalos-label>
```

4. Verify generated snapshot files exist:

- `thalos_versioned_docs/version-<old-label>/`
- `thalos_versioned_sidebars/version-<old-label>-sidebars.json`
- `thalos_versions.json`

5. Update current docs and bump `thalosConfig.versions.current.label` to the user-requested new label.
6. Run `npm run build` and record warnings separately from failures.
7. Commit generated versioned docs plus current doc/config changes. Do not commit `.codebase-memory/` unless explicitly requested.

## Content checklist for nibble FSM updates

When the FSM is refactored, the docs usually need more than state-name edits:

- Mermaid diagram transitions must match `NIBBLE_TRANSITIONS`.
- For Thalos FSM Mermaid diagrams, prefer the mission-FSM visual style: group all states that can terminate into a `subgraph terminable [Terminable]` and draw a single `terminable -- terminate --> terminated` edge instead of one terminate edge per state.
- Quick reference state count and phase grouping must match `NibbleStateEnum`.
- Remove pass-through states that no longer exist as enum values.
- Update retry behavior from `NIBBLE_RETRY_TRANSITION_DICT`.
- Update terminal/error state descriptions from `NIBBLE_EXECUTION_TERMINAL_STATES` and `NIBBLE_EXECUTION_ERROR_STATES`.
- Document runtime semantics from `nibble_executor.py`, not just FSM edges.

## SART-1848-style semantics to preserve while current

For the SART-1848 nibble executor design, keep these points aligned with code if still true:

- Current nibble FSM states are: `IDLE`, `AWAIT_BLOCK_ENTRY`, `AWAIT_BLOCK_ENTRY_TIMEOUT_ERROR`, `ROUTE_REQUEST`, `ROUTE_REQUEST_ERROR`, `MA_REFRESH`, `MA_REFRESH_ERROR`, `AWAIT_BLOCK_EXIT`, `COMPLETED`, `TERMINATED`.
- `AWAIT_BLOCK_EXIT` completes a non-terminal nibble only after ADS reports `status.block_id != current block id`; `sub_block_id` is not used for exit completion.
- Terminal nibble completes from `AWAIT_BLOCK_EXIT` without waiting for block exit because the vehicle remains in the destination block at mission end.
- Relevant route/block/signal/TSR changes while in `AWAIT_BLOCK_EXIT` trigger `RECHECK` back to `ROUTE_REQUEST`.
- Route authority evaluation waits instead of requesting when a relevant block is occupied by something other than the mission vehicle, or when a route is owned by another mission / has unknown owner.
- Revoke + request is only for stale authority cases where the route appears authorized but a relevant controlled block lost authorization.
- ABS Direction is not currently a nibble-level authority check; do not leave stale recovery text saying to verify ABS Direction unless code has reintroduced it.
- MissionExecutor may keep one look-ahead nibble active so N+1 can wait for block entry while N waits for block exit.
