# TAPAS ICD Document Maintenance

## Overview

`/opt/data/workspace/tapas-icd` is the TAPAS Docusaurus documentation project. It contains three independently versioned document sets:

- `icd/` — TAPAS ICD current docs.
- `deployment/` — deployment current docs.
- `thalos/` — Thalos / Safety Server current docs.

The versioned snapshots are under `*_versioned_docs`, `*_versioned_sidebars`, and `*_versions.json`.

Core rule: **before changing current documents, first freeze the old version with the appropriate npm version script.** This preserves the previous published state before current docs move forward.

## Required First Steps

1. Inspect the repo state:

```bash
cd /opt/data/workspace/tapas-icd
git status --short
git branch --show-current
git log -1 --oneline
```

2. Use Codebase Memory for discovery if the task requires understanding project structure or locating definitions:

```text
mcp_codebase_memory_list_projects()
mcp_codebase_memory_index_repository(repo_path="/opt/data/workspace/tapas-icd", mode="moderate", persistence=true)
```

Use project name `opt-data-workspace-tapas-icd` after indexing.

3. Read these source-of-truth files before changing workflow-sensitive behavior:

- `package.json`
- `config/docs-config.ts`
- `icd/change-procedure.md`
- relevant current docs under `icd/`, `deployment/`, or `thalos/`

## Version-First Change Workflow

Choose the affected docs plugin and freeze the old current version **before editing**.

### ICD

Current label is in `config/docs-config.ts` under `icdDocsConfig.versions.current.label`.

```bash
npm run version:icd -- <current-icd-label>
```

Example:

```bash
npm run version:icd -- 1.2.6
```

Confirm updates:

- `icd_versioned_docs/version-<version>/`
- `icd_versioned_sidebars/version-<version>-sidebars.json`
- `icd_versions.json`

Then edit current docs in `icd/` and bump the current ICD patch version in `config/docs-config.ts` for the new working version.

### Deployment

Current label is in `deploymentDocsConfig.versions.current.label`.

```bash
npm run version:deployment -- <current-deployment-label>
```

Confirm updates:

- `deployment_versioned_docs/version-<version>/`
- `deployment_versioned_sidebars/version-<version>-sidebars.json`
- `deployment_versions.json`

Then edit `deployment/`.

### Thalos

Current label is in `thalosConfig.versions.current.label`.

```bash
npm run version:thalos -- <current-thalos-label>
```

Confirm updates:

- `thalos_versioned_docs/version-<version>/`
- `thalos_versioned_sidebars/version-<version>-sidebars.json`
- `thalos_versions.json`

Then edit `thalos/`.

## Editing ICD Pages

ICD pages are MDX files under `icd/`. Message format pages usually use shared React table components.

Use `IcdTable` for message fields:

```tsx
import { IcdTable } from "@site/src/components/icd";

<IcdTable
  rows={[
    { id: "1", name: "Speed", mandatory: true, type: "UINT16", notes: "km/h" },
  ]}
/>;
```

Use shared enum data when values repeat across pages:

1. Create `icd/enums/<name>.ts`.
2. Export rows using the relevant table row type.
3. Re-export from `icd/enums/index.ts`.
4. Import from MDX and render with `IcdEnumTable`, `DomEnumTable`, or `SeverityEventEnumTable` as appropriate.

## Adding Pages

Add new pages to the current docs directory, not directly to `*_versioned_docs`.

Use frontmatter:

```mdx
---
sidebar_position: 20
title: Type 20 - Example
---
```

The sidebar is autogenerated by `config/sidebar-config.ts`; normally do not hand-edit sidebar JSON.

## Validation

Run validation after edits:

```bash
npm install   # if node_modules is missing
npm run build
```

Known repository state from prior research:

- `npm run build` succeeds.
- `npm run typecheck` currently fails because of an existing generic ReactNode type issue in `src/components/icd/Table.tsx:46`.
- Docusaurus build may warn about a broken anchor in `/icd/latest/type-02-vs` pointing to `#ark-code-snapshots`.

Do not claim typecheck passes unless it has been fixed and rerun.

## Preview and Deployment Flow

Repo source-of-truth files:

- `build-icd.sh`
- `deploy-icd.sh`
- `Jenkinsfile`
- `icd/change-procedure.md`

Expected Gerrit/Jenkins behavior:

- `patchset-created`: Jenkins runs `./build-icd.sh <changeNum>` and deploys preview to `http://10.2.10.51/<changeNum>`.
- `change-merged`: Jenkins runs `./build-icd.sh master`, deploys production to `http://10.2.10.51`, and cleans the preview directory.

Local build commands:

```bash
./build-icd.sh master
./build-icd.sh <change-number>
```

These use Docker and set Docusaurus `baseUrl` to `/` or `/<change-number>/`.

## Generated Files and Git Hygiene

Expected generated/ignored dirs:

- `node_modules/`
- `build/`
- `builds/`

Codebase Memory may create:

- `.codebase-memory/graph.db.zst`

Treat `.codebase-memory/` as a deliberate policy choice: commit it only if the team wants to share the graph artifact; otherwise remove it or ignore it before submitting a document change.

## Common Mistakes

- **Mistake:** Edit `icd/` first, then version afterward.  
  **Fix:** freeze the old current version first with `npm run version:icd -- <current-label>`.

- **Mistake:** Edit `*_versioned_docs` for normal changes.  
  **Fix:** normal work happens in current docs; versioned docs are frozen snapshots unless explicitly hotfixing an old version.

- **Mistake:** Run `npm run version:icd` without a version argument.  
  **Fix:** Docusaurus requires `<version>`: `npm run version:icd -- 1.2.6`.

- **Mistake:** Forget to bump `config/docs-config.ts` after ICD changes.  
  **Fix:** after freezing old current and editing ICD current docs, bump the ICD current label to the new patch version.

- **Mistake:** Trust README blindly.  
  **Fix:** README has had stale project-structure text; verify against live files and config.

## Quick Checklist

1. `git status --short`
2. Read relevant source files.
3. Freeze old version with the correct `npm run version:* -- <current-label>`.
4. Verify versioned docs/sidebars/version JSON changed as expected.
5. Edit current docs.
6. Bump current label when ICD docs change.
7. Run `npm run build`.
8. Review git diff; avoid accidental generated artifacts.
9. Submit to Gerrit and use Jenkins preview URL for review.
